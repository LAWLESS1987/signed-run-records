## ChatGPT's answer

I would not send v1 as-is. The packet is useful for checking what runs under a handful of controlled inputs. The internal results show the baseline and all six altered variants separating as intended. But a green result does not yet establish the advertised signed-body binding or read-once claims, and the executable review surface is materially larger than the invitations promised.

This was a static review, not an independent execution. I checked that the run_packet.py and expected.json bytes in the attachment match the SHA-256 values in RUNS.md. The attachment documents the pre-registration at 024cb2f, but does not independently establish the commit chronology. I compared the packet against the invitation promises as quoted in your request.

Blocking — expected.json, cases 1–4, and run_packet.py, one_case() and MUTATIONS. Every signed case uses the same JSON body, and the only unsigned case has no signature headers. A verifier that ignores the body digest or accepts any nonempty signature for a registered key could still produce the entire expected matrix. The no_signature_check variant removes the whole door check, so it cannot distinguish either narrower regression. Fix: Pre-register a negative where the submitted body differs from the signed body but otherwise authorizes the on-disk fixture, and one with an invalid signature for the registered throwaway key. Require no launch attempt in both. Add a control that specifically breaks body verification, or narrow the reproduced claim to the behavior of the supplied signed fixtures.

Blocking — CLAIM.md, “Reads once,” README.md §5, and run_packet.py, judge() and the pinned_expected_detail reporting block. Cases 5a/5b measure which fixture makes a marker under two swap schedules. They do not count reads. A second read whose bytes are discarded can pass both. So can no launch and no swap at all. On the pinned variant, approved_ran is printed as pre-registered but is not enforced, so exit 0 can mean neither swap case demonstrated that the approved bytes survived the swap. The internal record is candid about the no-launch behavior, but the README says a missing swap fails. Fix: Separate “no substitute observed” from “swap exercised and approved bytes ran.” Require the latter on the pinned code for both schedules, and report no launch separately for the always-refuse control. Either instrument target-file reads in the parent and runner, or make “read once” a source finding and describe the runtime test as a swap check.

Blocking — README.md §1, “Please read everything” and “The covenant code under test is not small,” versus the invitation’s “every file is small.” The harness is 482 lines, but it imports eight Covenant modules totaling 20,751 lines, including a 14,050-line core. The excerpts are a useful map of the claim, not the full code that can execute at import. Fix: Correct the invitation before the reviewer agrees to run it. Distinguish the small packet, the short claim-relevant excerpts, and the full executable source. If a small executable review surface is non-negotiable, the current packet does not meet it.

Should fix — run_packet.py, one_case() exception handler, audit(), and judge(). Cases 2–4 pass on zero markers and zero subprocess.Popen audit events even if a case-specific exception prevented the guard from being reached. Case 1 rules out a global failure, not those failures. Conversely, a Popen audit event counts a launch attempt, not proof the OS started a child. Case 1 can fail with the guards working if launch or marker creation fails, and a negative can fail on an unrelated launch attempt. Fix: Make unexpected fixture or branch errors inconclusive, not successful refusals, and report launch attempts separately from confirmed execution. Keep verdict text and ledger rows out of the scoring. The matched marker in case 1 is good positive evidence.

Should fix — README.md §5, cases 2–4, and run_packet.py, fixture selection and app.test_request_context(...). Case 2 checks one conspicuously different script, not rejection of a byte-only difference. Case 3 checks one two-token argument tail, so a guard that rejects those tokens but allows a single positional argument could pass. Case 4 checks omitted headers without explicitly setting a caller address, so it does not substantiate “loopback included.” The approved marker in case 1 also does not establish that the child received no extra arguments. Fix: Add a harmless byte-only change, a single positional argument, an explicitly loopback unsigned request, and an execution observation for child arguments. Add a validly signed request with a missing digest and a valid signature from an unregistered throwaway key if those are to be reproduced claims. Otherwise leave them explicitly as source findings.

Should fix — run_packet.py, keep_swapping(), gate(), swap_then_launch(), and judge()’s probe_on_disk_after check. 5a orders the replacement before launch, which makes it the stronger check. 5b starts a thread but does not wait for its first successful replacement. The final disk contents can show SUBSTITUTE even if the first swap came after the relevant read or launch. That can let a reread go undetected or make the altered variant behave differently across machines. A pinned run can also fail because the fixture never achieved the intended swap. Fix: Confirm the first replacement before returning from the gate, record event order independently of the final disk state, and classify a failed swap setup as inconclusive. Require the exact approved marker contents in case 5, as case 1 already does.

Should fix — README.md §6, expected.json variant_rule, and RUNS.md, “What the runs showed beyond pass and fail.” The seven variants do show that the checks can fail. The attached summary shows always-refuse failing case 1, accept-everything failing 2–4 and both swap subcases, and the four targeted breaks separating on their intended cases. But matching the set of failures is weaker than matching the evidence. In Windows 5b, child_reopens failed with a child launch and no approved marker, not with observed substitute execution. Fix: Pre-register the expected observations for each altered variant and distinguish substitute execution, a launch with no marker, and a fixture failure. The most useful additional read-once control is a harmless extra parent read that leaves execution unchanged. It should fail a literal read-count check while passing the existing behavioral check.

Should fix — CLAIM.md, “The door,” “The hands,” and “Signed,” against covenant_mycelium.py 114–166 and covenant_tetsu_hands.py 764–799, 905–1033. The excerpts support the normal captured-byte path and the argument refusal. But _request_signed_by_registered() accepts the boolean from admit(), which also has a signed:ally branch. The excerpt does not establish whether /m/agent is excluded from every effective ally scope, and the packet uses no allies. Also, _capture() follows parsing and does a path check before opening. “Before anything else” and the categorical link wording go further than that code. Unsigned refusal means no script launch, not no read, judge call, or ledger write. Fix: Qualify the signer-registry statement until the ally-scope restriction is shown, and describe the order and path check literally. Call nonce tracking in-memory, and distinguish the size of the generated test key from any key-size rule enforced by verification.

Should fix — README.md §1, “writes there and into the output folder, and nowhere else” and “the run does not” need network, plus run_packet.py, audit(), fetch_sources(), and worker environment setup. The hook observes selected Python audit events in the worker, not the launcher, Git, or the script child. It is not a filesystem boundary or an egress check. The worker inherits non-`COVENANT_` environment variables, and an incomplete Git clone can try to fetch missing objects. The evidence supports “no project credentials are required” and “no worker socket events were observed,” not “credentials are inaccessible” or “all processes were offline.” Fix: State that the run needs no network after setup with complete local inputs. Recommend the verified plain-folder path for the offline run and ask the reviewer to record whether networking was disabled. Replace the absolute write claim with the actual audit scope. Keep §8’s explicit containment exclusion.

Should fix — README.md §§2–4 and §7, and run_packet.py, fetch_sources() and main(). An experienced reviewer can probably get through setup, but the literal command is not portable as written. python may be absent on macOS/Linux, bare pip can target a different interpreter, and the fetch example’s && is not portable to Windows PowerShell 5.1. It is also unclear which extracted directory to pass. A missing source file, unavailable Git executable, or worker timeout can escape the promised exit-2 handling. Fix: Give minimal macOS/Linux and Windows commands that use the same interpreter for installation and execution, show where to run them and which ZIP directory to pass, and make those setup errors produce the documented result. Say Windows and WSL2 tested, native Linux and macOS not independently verified, and list the tested dependency combinations alongside the minimum version.

Minor — README.md §1 and §8, RUNS.md, and REVIEWER_RETURN.md. The README calls it a three-file packet and then names two more files. CLAIM.md refers to four Covenant tests “named in the README,” but their full list is in RUNS.md. The return template asks for raw records that can include absolute local paths. Fix: List three runnable inputs and two supporting documents explicitly, correct the test reference, and tell reviewers what they may redact before sharing.

The packet does deliver a full Covenant pin with blob checks, one run command after setup, temporary fixture workspaces, throwaway keys, five numbered cases with case 5 split in two, recorded pre-registered outcomes, marker-based scoring instead of verdict-text scoring, both headline controls, and measured timings with dependency versions. I’d keep those strengths. Before sending, I’d make exit 0 mean the pinned swap checks actually ran, add a direct check of signed-body binding, and correct the read-surface promise.
